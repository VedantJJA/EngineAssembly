# Engine collision assets

The desktop and mobile workshop scenes use CoACD convex hulls on each of the 318 physical engine components. `Assets/Prefabs/ThreeCylinderEngine_CoACD.prefab` is the reusable assembled model with its materials and collider hierarchy. Use a Unity prefab to retain these collision components; FBX does not store Unity MeshCollider settings.

The current validated hull meshes live in `Assets/GeneratedColliders/EngineCoACDValidated`: 96 shared geometry sets, with 4,475 hull instances per complete engine. All 318 physical parts have exact CAD collision surfaces while static, installed or carried, and use their convex hulls when released dynamically. Parts, bearing components and split caps remain separate; generating colliders does not combine their rendered meshes or alter assembly order. Old broad colliders are disabled and replaced by children named `Generated Colliders (CoACD)`.

Hull vertices are centred and normalized before native PhysX cooking. Each collider child restores the original CAD centre and scale, retaining the model's geometry while avoiding QuickHull failures on tiny imported coordinates. Zero-volume fragments are discarded; every remaining hull must pass Unity's convex bake before existing scene colliders are replaced. The saved `ColliderHullSet` assets retain both mesh references and their coordinate frames.

The normal bake requests a concavity threshold of 0.04, up to 24 convex hulls per mesh, and at most 64 vertices per hull. Housings that exceed the 15-minute search limit use `retry_engine.py`: threshold 0.1 with a bounded search. CoACD may exceed the requested concavity when the hull limit is reached, so these remain collision approximations. Picking and ghost line-of-sight use the visible CAD meshes independently of these hulls. Android performance still needs verification on the target device.

The original `GSwirl_Wires` source contains 36 vertices and edges but **no faces**. Its FBX mesh therefore had no usable Unity surface. `Tools/EngineModel/build_wire_surface.py` creates a thin visual sleeve along the preserved routing in a separate FBX; `909_Motor_Wiring_Surface.asset` converts it into the original part's local frame. The original Blender file is untouched. The sleeve radius is a presentation choice, not a calibrated CAD measurement.

## Rebuilding

For the head, use **Detailed CAD cavities** in Batch Setup Parts. This selects threshold 0.02, 75-level preprocessing, 2,000 distance samples, 128 vertices per hull and a 256-hull limit (adjustable). It has a configurable per-mesh time limit (60 minutes by default for detailed jobs), elapsed time, backend progress and a persistent job log in `Library/AssemblyColliderJobs`. The Python bridge clamps Unity's float representation of the minimum threshold to exactly 0.01, caches completed native results, and filters zero-volume fragments that cannot represent solid colliders. The initial uncapped 0.01 head run produced 4,776 fragments including invalid solids; the bounded profile is used instead. Settings follow the [CoACD parameter documentation](https://github.com/SarahWeiii/CoACD#parameters).

The validated folder includes the normalized dedicated head hulls, generated from the current head geometry with the detailed profile. Both workshop scenes and the full engine prefab use the validated assets; `Assets/Prefabs/CylinderHead_Precise.prefab` is a reusable head. Its `AssemblyPrecisionSurface` uses the exact CAD MeshCollider while kinematic or static, preserving the valve bores, and switches to the detailed convex hulls when released dynamically. Collider contact offsets are 1 mm. **Tools → Engine Assembly → Apply Precise Cylinder Head** applies the matching geometry bake to heads in the open scene with Undo, retaining unrelated edits. It rejects a missing geometry match instead of falling back to a stale head bake.

The corrected head bake contains 256 hulls. CoACD reported a maximum concavity of 0.06006 after reaching that hull limit; these dynamic colliders remain an approximation. The exact static/kinematic surface preserves the openings used during assembly. Native Unity geometry probes confirmed all 12 valve bores were clear and detected 27 sampled solid surfaces. Installed subassembly handling boxes are disabled so they cannot fill these cavities. All 73 chapter and subassembly regression checks passed with the updated head in the mobile scene; target-device performance remains unmeasured.

`CylinderHeadExactNormalized.asset` is the head's exact static/kinematic collision mesh. Its coordinates are centred and normalized before cooking, with vertex welding disabled, then its child transform restores the original CAD frame. All convex head hulls remain disabled during assembly. Exact ghost and pickup queries use the same normalization independently of the simulation hulls. Regenerating this asset refreshes its geometry instead of retaining a stale cached mesh.

The corrected head comes from `Part16` in `Assets/Model/3cyl.blend`. Only that mesh was transferred into the existing labelled Blender file and FBX; all 318 part IDs, parents and assembly poses remain unchanged. Blender surface probes confirmed access to all twelve spring seats and twelve stem seals. Native Unity checks passed all 72 valve-stack placements with ghosts at their final CAD poses. Head hull assets are selected by the current source geometry hash to prevent reusing the previous head's decomposition.

`EngineColliderBake.Export` writes a mesh manifest and CoACD requests into `Tools/Colliders/EngineBake`. Run `Tools/Colliders/bake_engine.py` with that folder as its argument and the Python installation configured in `Tools/Colliders/settings.local.json`. The process resumes from completed results. `EngineColliderBake.Apply` imports the hulls, updates both workshop scenes and exports the prefab; run it in the isolated batch project to preserve open scene edits, then copy the generated assets and their `.meta` files together.

For individual scene changes, use **Tools → Engine Assembly → Batch Setup Parts**, select the desired roots or **Select all**, and choose **CoACD**. Retain the original CAD sources and recipe IDs.

## Interaction corrections

The PC crosshair is anchored to the exact screen centre at every aspect ratio. Pickup and ghost queries ignore the player's own collider hierarchy and held inventory while respecting solid environment occlusion. Standing and crouching use the same selection logic. Exact CAD picking accepts both face windings within its query without changing the global physics setting. There is no global Move mode; Q selects carry/placement and R selects mouse rotation/movement. See `AssemblyWorkshop.md` for controls and stacking rules.
